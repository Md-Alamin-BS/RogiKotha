### Summary

The adapter design holds up. The application layer stays free of Better Auth, the `/api/auth` route answers only `/api/auth/ok`, the session and user hooks work only inside a gateway scope, the worker holds only the mail-only key, logs and audit rows use allowlists, and en/bn parity is kept. Two runtime problems need fixing before this Unit is relied on: library calls run inside an open command transaction on a 10-connection pool with no acquire timeout, so about 10 parallel successful sign-ins hang the web process; and the sign-in and change-password limits are checked before the attempt is recorded, so parallel requests get past them.
