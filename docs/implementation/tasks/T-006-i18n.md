## Goal

Move every bilingual string the prototype ships — 568 keys in `STRINGS`, the viewer's `VIEWER_STRINGS`, the admin nav group labels — into `packages/i18n/messages/en.json` and `bn.json` **by script**, add the auth/staff/email/error keys from the auth spec, enforce parity with a test, and provide the number/date formatters and the next-intl configuration the web app will load. No copy is edited except the one reword the plan requires.

## Steps

1. `pnpm --filter @rogikotha/i18n add next-intl@^4.14.2` (peer: next/react are installed by T-008; add them as `peerDependencies` here, not dependencies).
2. `scripts/port-from-prototype.mjs`: load `ui-design-prototype/shared/rogikotha-data.js` in a `vm` context with a stub `window`/`document`/`localStorage` (the same trick the plan's author used: `vm.runInContext(src, { window: {}, document: { querySelectorAll: () => [] }, localStorage: { getItem: () => null, setItem() {} } })`), read `window.RK.strings`; also read `VIEWER_STRINGS` by regex-extracting the object literal from the 04b `app.js` (it is a plain object of `{ key: { en, bn } }` — `eval` it in the same vm), and hard-code the two `NAV_GROUPS` labels as `admin.nav.casework` / `admin.nav.oversight`. Convert `'a.b.c': {en, bn}` into nested objects (`{ a: { b: { c: 'en text' } } }`) — **conflicts** (a key that is both a leaf and a namespace, e.g. `compose.identity` and `compose.identity.real`) must be resolved deterministically: rename the leaf to `<key>.label` and print every rename to stdout; T-008+ components use the renamed key. Emit sorted JSON with 2-space indent, `\n` line endings, no BOM (Windows gotcha: write with `fs.writeFileSync(path, json, 'utf8')`, never PowerShell `Out-File`). Viewer keys go under `viewer.*`.
3. Apply the one required reword in the script (so it is reproducible): `demo.banner` → en `Demo — fictional records, not a real service`, bn `ডেমো — কাল্পনিক তথ্য, বাস্তব সেবা নয়`. Remove the `demo.role.*`, `demo.scheme*`, `demo.reset`, `demo.close`, `demo.roleNote`, `demo.title`, `write.signinTitle`, `write.signinBody`, `concept.back`, `admin.backToGallery`, `admin.role.current`, `admin.role.currentTitle`, `admin.act.cycleTip`, `admin.demoNote` keys (the demo panel, scheme picker and role switcher are not ported — master plan §1, auth spec §1/§4) and print the removed list.
4. Append the auth-spec table: copy every row of `docs/design/auth-screens-spec.md` §5 into a JSON file `scripts/auth-keys.json` (`{ "auth.kicker": { "en": "…", "bn": "…" }, … }`) **verbatim** — no rewording — and merge it in the port script. Also add `errors.common.forbidden`, `errors.common.notFound`, `errors.common.conflict`, `errors.common.validation`, `errors.common.rateLimited`, `errors.common.internal` and the remaining `errors.*` keys for **every** code in `@rogikotha/contracts` `ERROR_CODES` with plain EN/BN sentences (write them in `scripts/error-keys.json`; keep each ≤ 12 words; Bengali must be real Bengali, not transliteration). List those you wrote in the hand-off for the founder's bilingual review.
5. Run the script: `pnpm --filter @rogikotha/i18n port` → writes both JSON files. Commit the script **and** the output; the script is the audit trail.
6. `scripts/check-parity.mjs` (script `check`): flattens both files, fails (exit 1) listing keys present in one and missing in the other, empty strings, values that are identical in both languages for keys outside an allowlist (`brand.name` en/bn differ; usernames like `shirin_88` are data, not strings — allowlist `auth.termsLink`? no — allowlist only keys whose value is a number/phone or a Latin proper noun: `emergview.*` phone numbers if any, `viewer.*` numeric labels; keep the allowlist in the script and print it), and any `{param}` placeholder present in one language but not the other. Also fails if any `ERROR_CODES` entry from contracts lacks its `errors.*` key (import the array from `../../contracts/src/errors.ts` via `tsx`? Simpler: the contracts package exports `ERROR_CODES` from `src/errors.ts`; read it with a regex in the script to stay dependency-free).
7. `scripts/gen-keys.mjs` (script `keys`): emits `src/keys.ts` with `export type MessageKey = 'a.b.c' | …` from `en.json`, and `export const MESSAGE_KEYS: readonly MessageKey[]`. Committed output; `check` also verifies it is up to date.
8. `src/format.ts`:
   - `BENGALI_DIGITS = ['০','১','২','৩','৪','৫','৬','৭','৮','৯']`; `formatNumber(n: number, locale: Locale): string` → `Intl.NumberFormat('en-US')` grouping then digit substitution for `bn` (matches the prototype's `bn()`: replaces `0-9` only; keeps Latin thousands separators — confirm against `app.js:54` and note if the prototype used Bengali commas).
   - `formatMonthYear({year, month}, locale)` → `March 2026` / `মার্চ ২০২৬` using a local month-name table (Intl's Bengali month names are acceptable if they match the prototype's `period.bn` strings — compare with `RK.reviews[0].period.bn`; use whichever matches).
   - `formatRelative(from: Date, to: Date, locale)` → the prototype's `relTime()` semantics (`admin/app.js:671`) with the `admin.timeline.timeAgo` style, Bengali digits for `bn`.
   - `formatCount(count, total, locale)` → `"3 of 5"` / `"৫টির মধ্যে ৩"` using the existing `sentiment.of` key pattern (`{count}` / `{total}` params) — implement as a helper that returns params, not text, since text comes from next-intl; export `countParams(count, total, locale)` returning `{ count: formatNumber(count, locale), total: formatNumber(total, locale) }`.
9. `src/routing.ts`: `defineRouting({ locales: ['en','bn'], defaultLocale: 'en', localePrefix: 'always', localeCookie: { name: 'rk.lang' } })` and `export const { Link, redirect, usePathname, useRouter, getPathname } = createNavigation(routing)`. `src/request.ts`: `getRequestConfig` loading `messages/<locale>.json`, `timeZone: 'Asia/Dhaka'`, and `onError` that **throws in development and test** for a missing key (a missing key must fail the build, not render the key name).
10. `vitest.config.ts` environment `node`. Tests in step "Tests to write". Scripts in `package.json`: `port`, `check`, `keys`, `test`, `typecheck`. Root `pnpm i18n:check` (from T-001) now resolves.
11. Commit: `T-006: i18n dictionaries ported from the prototype, parity check, formatters`.
