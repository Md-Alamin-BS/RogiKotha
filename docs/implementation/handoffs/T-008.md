## What exists now

`apps/web` is a runnable Next.js 16.3.4 App Router app: `pnpm --filter @rogikotha/web dev` serves
`/en`, `/bn`, `/en/admin/queue`, etc. `/{locale}` routing (next-intl, `localePrefix: 'always'`,
`rk.lang`/`rk.theme`/`rk.motion` cookies) works both ways — bare `/` redirects by cookie/
Accept-Language, the `অ` control switches locale via a real link. The three ported stylesheets
(`src/styles/{tokens,patient,admin}.css`) are byte-for-byte copies of the prototype (`diff` clean).
Patient chrome (`Masthead`, `Tabs`, `ThemeControls`, `Colophon`, `SkipLink`, `DemoMarker`) and staff
chrome (`Masthead`, `ConsoleNav`, `TabBar`, `Crumbs`, `Colophon`) both render, themed and grouped
per the prototype, with `data-app`/`data-view` scoping so `patient.css`/`admin.css` never collide.
Every URL in `03-routes-and-contracts.md` §1 has a placeholder `page.tsx` (title + `h1.display` +
"This screen arrives with task T-xxx" note), each already `noindex` where the prototype's
`setNoindex(true)` said so (`/me*`, `/authors/*`, `/admin/*`, auth routes). `/api/health` returns the
stub shape T-101/T-009/T-304 will fill in. `Sheet` (focus trap, Escape, focus-return) and `LiveRegion`
(`useAnnounce`, clears after 1s) are ready primitives with no content wired to them yet.

## Fragile or surprising

- **`proxy.ts` must live at `apps/web/src/proxy.ts`, not `apps/web/proxy.ts`** (`ISS-084`, fixed here)
  — Next.js's file discovery resolves it beside the `app` directory's *parent*, which is `src/` in
  this layout. A proxy at the package root compiles fine and produces no error; it is just silently
  never invoked (no `ƒ Proxy (Middleware)` line in `next build`'s route table, no `x-pathname` header
  ever reaches a layout). If you move `apps/web/app` back to the package root in some future
  refactor, `proxy.ts` needs to move with it.
- **Windows dev-server port cleanup**: `pnpm --filter @rogikotha/web dev` in the background leaves a
  `node.exe` holding port 3000 after this session; `netstat -ano | grep :3000` +
  `powershell -Command "Stop-Process -Id <pid> -Force"` is what worked from Git Bash (plain `pkill`
  didn't match the process).
- **Testing next-intl's `Link`/`usePathname`**: don't mock `next/navigation` directly (next-intl's
  own internal resolution of it breaks under Vitest — `Cannot find module '.../next/navigation'`,
  a next-intl dev-build resolution quirk, not something in our control). Mock this app's own
  `@/i18n/routing` re-export instead; every component test that needs `Link`/`usePathname` does this
  (see `Masthead.test.tsx`'s comment).
- **`@testing-library/react`'s auto-cleanup never fires** unless `vitest.config.ts` sets
  `test.globals: true` (which this repo deliberately doesn't, to match every other package). Fixed by
  registering `cleanup()` in an explicit `afterEach` in `vitest.setup.ts` — without it, two tests in
  the same file that each call `render()` collide.
- **jsdom never computes layout**: `offsetWidth`/`offsetHeight` are always 0, so the prototype's own
  focus-trap visibility filter (`el.offsetWidth > 0 || el.offsetHeight > 0`) would treat every
  element as invisible under a naive test. `Sheet.test.tsx` patches `HTMLElement.prototype` in
  `beforeAll` to work around this — a test-only shim, not a product code change.
- **`next dev` auto-writes `apps/web/{AGENTS,CLAUDE}.md`** (Next 16's `agentRules` feature) unless
  disabled in `next.config.ts` (`ISS-091`, fixed here). If you ever see those two files show up as
  untracked in `git status` after running `next dev`, delete them — they're not part of this task.
