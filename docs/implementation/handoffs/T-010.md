## Review fixes (2026-10-29, review R-01 to R-05)

- **R-01 (Major).** The worker's ban on value imports of application code no longer keys on the
  import name alone: `boundaryBans` (was `dynamicBans`) in `eslint.boundaries.mjs` also refuses a
  static value import or re-export that resolves to the `application` element by any specifier
  other than `@rogikotha/application` and its subpaths, which `no-restricted-imports` already
  owns (only `/worker` passes). Type-only imports stay allowed; `import { type X }` counts as a
  value import because it still loads the module. Fixture FX16 (relative value import of
  `packages/application/src/index`) is refused, control FX21 (the same path, type-only) is not.
- **R-02.** Fixture FX17 (`await import('better-auth')` in the worker), FX18 (`require('pg')`
  through `createRequire`; a bare `require` would also trip `@typescript-eslint/no-require-imports`)
  and FX19 (`await import('node:fs')` in a component) prove the dynamic-import policies.
- **R-03.** `web-shared` source (`apps/web/src/lib`, `apps/web/src/i18n`) carries the component
  limits: no Node built-ins and no component-banned server library, by any import kind. No file
