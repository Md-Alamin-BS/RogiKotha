## Fragile or surprising

- The task file's literal compose snippet **does not start** against the current `postgres:18`
  image: it now wants the volume mounted at `/var/lib/postgresql`, not `.../data` (`ISS-040`). If
  you ever revert `docker-compose.yml` to the task file's exact text, the postgres container will
  exit immediately with "PostgreSQL data in /var/lib/postgresql/data (unused mount/volume)".
- ClamAV's custom signature file **cannot** be bind-mounted read-only — the image's entrypoint
  chowns the whole `/var/lib/clamav` tree on every start and errors on a read-only file
  (`ISS-041`). It's mounted read-write instead.
- `axllent/mailpit:latest` in the task text was already stale; pinned to `v1.31.1` per the fresh
  2026-09-13 dependency check (`ISS-039`).
- ClamAV came up `healthy` in about a minute in this run (a cached/fast signature mirror), not the
  "several minutes" the task file describes — don't assume that timing; the `start_period: 600s`
  headroom is still there for a slower pull.
