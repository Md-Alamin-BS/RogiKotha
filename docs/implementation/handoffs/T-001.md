## Fragile or surprising

- Vitest 4.1.11 dropped `defineWorkspace`/auto-loaded `vitest.workspace.ts`. The file still exists
  under that name with the same two globs, but it is a plain `defineConfig({ test: { projects } })`
  and every script that runs tests passes `--config vitest.workspace.ts` explicitly. If you add a
  root test script that runs Vitest, add that flag or it will silently run as a bare single-project
  config with none of the workspace projects. `ISS-004`.
- Vitest's CLI filter argument is a substring match, not a glob (`pnpm smoke` uses `smoke.test`).
  `ISS-006`.
- `apps/web`'s `typecheck`/`dev`/`build` are all `echo "T-008"` placeholders — there is no
  `apps/web/src` yet. Don't `pnpm --filter @rogikotha/web typecheck` expecting a real check until
  T-008 lands.
- ESLint's type-aware linting (`projectService: true`) only covers files inside a package's own
  `src/`. Any new root-level `*.ts`/`*.mjs` config file needs adding to the `disableTypeChecked`
  override in `eslint.config.mjs`, or its own tsconfig coverage. `ISS-002`.
- This checkout already had `.agents/`, `.claude/`, `.github/`, `.impeccable/` directories with
  third-party skill scripts; they're now in the ESLint `ignores` list. If `pnpm lint` starts
  failing on files under one of those paths again, that path likely needs adding too. `ISS-003`.
