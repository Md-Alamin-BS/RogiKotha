## Static vs. must-become-real

Everything is `state.session` (patient) / `state.staffSignedIn` + `state.deviceTrusted` (staff)
flipping in memory — no network, no hashing, no real tokens, no cookies. When porting:
- Register/sign-in/reset forms submit client-side only; port to server actions per
  `01-conventions.md` §8, keeping field order, `aria-*`, and the `.field-error`/summary pattern.
- The "simulate the emailed link" controls (`data-verify-simulate`, `data-reset-simulate`,
  `data-approve-simulate`) stand in for a real email + `?token=` round trip — there is no
  query-string router here (ISS-030). The real routes are `/verify-email?token=`,
  `/reset-password?token=`, `/admin/approve-device?token=`.
- Rate limiting and account-suspended states are copy-only (`errors.auth.rateLimited`,
  `errors.auth.accountSuspended`) — no counter exists yet (ISS-032). "Password ≠ email" is not
  enforced (ISS-033).
- `openStepUp`/`openStepUp` (patient/admin) simulate the 5-minute step-up grace window via
  `state.stepUpUntil = Date.now() + 5*60*1000` — the real version is server-side and per-session.
- `/me` content ("Published"/"Drafts") is the fixed `RK.user` fixture regardless of which demo
  account is "signed in" (ISS-029) — expect real per-user data once T-006/T-1xx wire a database.

## Fragile or surprising

- **Field ids are namespaced `f-<view>-<name>`** (e.g. `f-register-email`, `f-signin-email`) because
  every auth view is mounted in the DOM at once (only `hidden` toggles) — a bare `f-email` collided
  between `/register` and `/sign-in`. Keep this convention or scope ids per route component instead.
- **`admin/styles.css` needed a `[hidden]` override** (`.bar-nav[hidden], .tabbar[hidden],
  .crumbs[hidden] { display:none; }`, appended near the end of the file) — those classes set an
  unconditional `display` with no such rule, so `el.hidden` alone did nothing (ISS-026, found via
  the browser walkthrough, not jsdom — jsdom does not compute `display`).
- **`admin/app.js` has no `.link-btn` class** — password Show/Hide there reuses `.btn.ghost.small`
  (ISS-024). Port both consoles' toggle to whatever button primitive the design system settles on.
- Terms/Privacy links point at `#about` (ISS-028) — there is no `/terms` or `/privacy` route yet.
- `route()` in 04b now also calls `renderMine()` when navigating to `#me` (not just the five new
  views) so the one-shot "email confirmed" banner (`state.verifyWelcome`) shows correctly (ISS-031).
