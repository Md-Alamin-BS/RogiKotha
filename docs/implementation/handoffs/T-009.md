## What exists now

`apps/worker` is a real runnable Node process: `pnpm dev:worker` connects to PostgreSQL as
`rk_worker`, starts pg-boss, relays `outbox_events` into pg-boss jobs every 2 s using the event→job
map from 03-routes-and-contracts.md §5, logs structured JSON (`worker.started`, `worker.heartbeat`
every 60 s, `worker.stopping`/`worker.stopped`), and shuts down gracefully. `packages/database`
gained a `queue/` module (`PgBossQueue`, `installPgBoss`) and a new migration
(`0006_pgboss_grants.sql`) that grants `rk_worker` USAGE + DML on the `pgboss` schema, which
`migrate.ts` now installs as `rk_app` before the SQL migrations run. No business job handlers yet —
later tasks add one file under `handlers/` and one line in `registry.ts`'s `JOBS`.

## Fragile or surprising

- **A log field named `event` silently overwrote the log line's own event name (`ISS-192`, found and
  fixed here).** `logger.ts`'s `write()` originally spread caller fields *after* the fixed
  `{ ts, level, event }` keys — `outbox-relay.ts` logging `{ event: outboxEvent.name, ... }` as a
  field replaced the line's own `"event": "outbox.unmapped"` with the outbox event's name instead.
  Only caught by actually running the worker and reading real log lines, not by the unit tests (which
  used a mocked `console.log` but never inspected a field named `event`). Fixed by spreading fields
  first so the envelope always wins; regression test added. If you write a new logger anywhere else in
  this codebase, spread caller fields before the fixed envelope keys, not after.
- **On Windows, `kill`/`child_process.kill('SIGTERM')` from outside a real console does not reliably
  reach a native `node.exe` process's `process.on('SIGTERM')` listener** — a documented Node/Windows
  limitation, not a bug in `main.ts`'s shutdown handler. Only an actual interactive Ctrl-C (or
  Ctrl-Break, or the `message:'shutdown'` IPC path this task's step 8 explicitly asks for) reliably
  triggers it. If you need to verify graceful shutdown non-interactively on this host, use
  `child_process.fork()` + `child.send('shutdown')`, not `child.kill(...)`.
- **`pg-boss`'s `migrate: false` constructor option is what makes the restricted-privilege
  `rk_worker` role safe to use at all** — without it, `boss.start()` attempts schema DDL the role
  cannot perform. This only works because `migrate.ts` installs/migrates the `pgboss` schema as
  `rk_app` *before* the worker ever starts (`installPgBoss`, run every `db:migrate`/`db:reset`). If a
  future session ever runs the worker against a database that has never had `pnpm db:migrate` run,
  `queue.start()` will throw rather than silently attempting DDL — that is the intended fail-closed
  behaviour, not a bug.
- **`apps/worker`'s own `build`/`start` scripts are not yet how the worker is actually run** — see
  `ISS-193`. `pnpm dev:worker` (`tsx watch`) is the supported path; it resolves every workspace
  package's TS source directly the way `tsx` always has in this repo.
