## Why this exists

A second, independent T-003 validation (`docs/validation/T-003-round-2.md`) found two **S2**
defects in `packages/contracts` after the first validation had already merged T-003 to `build/demo`
as `PASS`. Neither defect had an owner task — no queued task (`T-004`, `T-008`) declares
`packages/contracts/**` in its Owned paths — so the two findings sat as open `ISS-` rows with
nowhere to land. The founder then gave a standing instruction: fix small, well-specified, low-risk
findings like these immediately rather than only logging them; document the policy so a future
clean session can apply it without being told each time. That policy is now
`04-handoff-and-validation.md` §4.1 (cross-referenced from `LOOP.md`).

## What exists now

- **`ISS-077` fixed** — `packages/contracts/src/ids.ts`'s `newPublicId()` sliced hex chars 0-12 of a
  fresh UUIDv4, which includes the version nibble (always `4`) at index 12; every generated id's
  last character was therefore always `4` or `m` (46 bits of real entropy, not 50). Now slices chars
  19-31 (no version/variant nibble). Added a regression test in `ids.test.ts` asserting every one of
  the 10 output positions reaches more than 2 distinct symbols over 20,000 generated ids — the
  existing uniqueness test could not have caught this (50,000/50,000 unique ids is still true with a
  broken generator).
- **`ISS-078` fixed** — `auth.account_suspended` was specified by `docs/design/auth-screens-spec.md`
  and already shipped in both dictionaries (`errors.auth.accountSuspended`), but existed in no
  `ErrorCode` union. Added to `docs/implementation/03-routes-and-contracts.md` §2 (source of truth)
  first, then to `packages/contracts/src/errors.ts`'s `ERROR_CODES` in the same commit, per that
  file's own header rule ("do not invent codes here; add to that doc first").
- **New regression guard** — `packages/i18n/scripts/check-parity.mjs` now also checks the *reverse*
  direction: every `errors.*` dictionary key must have a matching `ErrorCode`, not just every code
  having a key. This is exactly the direction that let `ISS-078` ship undetected (the existing check
  only walked codes → keys). `pnpm i18n:check` still passes (764 keys, both directions clean).
- **Record corrections (`ISS-082`, `ISS-083`)** — `docs/implementation/handoffs/T-003.md`'s view-model
  count corrected 18 → 19 (matches what was actually on disk since T-003's original commit); its
  `Branch · commit` and `Run record` fields filled in with the real commit hashes/model, which were
  left as placeholders. `docs/implementation/tasks/T-003-contracts.md` Step 11's transposed owner map
  corrected (`thread`/`evidence` → `T-402`/`T-308`, matching what the code already did — no code
  changed, only the task-file prose).
- **New standing policy** — `04-handoff-and-validation.md` §4.1 ("Findings outside every currently
  queued task's owned paths") plus short cross-references in `LOOP.md` (§2 step 4, §5), so a future
  clean session knows when to fix a small out-of-scope finding immediately versus write it up as a
  `CR-nnn` mini task for later.
- **`ISS-055` fixed too** (found opportunistically while working on this CR, not part of the
  original ask) — every fresh worktree in this build has hit `ERR_PNPM_IGNORED_BUILDS` on its first
  install and needed a manual `pnpm approve-builds --all`, including this one; `pnpm-workspace.yaml`
  now commits a real `allowBuilds: { '@parcel/watcher': true, '@swc/core': true }` block instead of
  the placeholder stub pnpm kept auto-writing and every prior session kept reverting. Verified with
  `rm -rf node_modules && pnpm install` from scratch — exit 0, builds ran, no gate.

## Fragile or surprising

- This CR intentionally has **no separate fresh-session validation record** (`docs/validation/CR-002.md`
  does not exist). `04-handoff-and-validation.md` §3.2 requires "the implementer and validator are
  never the same session" for tasks; this is deliberately treated as the narrow exception §4.1
  describes for small, mechanical, founder-authorized fixes, since a second full loop turn for a
  two-line fix plus a doc-only addition would cost more than the fix itself. If this norm feels wrong
  in hindsight, tighten §4.1's size threshold rather than special-casing this one CR.
