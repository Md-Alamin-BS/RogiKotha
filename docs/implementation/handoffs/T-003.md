## Fragile or surprising

- `newPublicId()` cannot use `crypto.getRandomValues` as the task text suggests — this package's
  tsconfig has no `dom`/`@types/node` lib (01-conventions.md §2: "contracts -> zod only"). It draws
  randomness from `uuid.v4()` instead (`ISS-073`). If a future task adds `@types/node` to this
  package for an unrelated reason, this workaround does not need to change, but could be simplified.
- `page.ts`'s `encodeCursor`/`decodeCursor` are a hand-rolled base64url + UTF-8 codec, not
  `Buffer`/`btoa` — deliberately, so this package stays usable from a browser bundle or an edge
  runtime, not just Node. It is more code than the one-liner the task's wording implies; read the
  comment at the top of `page.ts` before "simplifying" it back to `Buffer`.
- Many schema names had to be qualified with a noun beyond the literal command verb
  (`PublishReviewInput` vs. `PublishEvidenceInput`, `DeleteReviewInput` vs.
  `RequestDataDeletionInput`, …) because `index.ts` flattens every schema file into one namespace
  with `export *` — two modules both had a bare `PublishInput`/`DeleteInput` before this. If you add
  a new command schema, grep the whole `schemas/` tree for the name first.
- The task's acceptance-check table expects "40" error codes; the actual, verified-correct count
  copied from `03-routes-and-contracts.md` §2 is 38 (`ISS-076`) — don't "fix" `ERROR_CODES` to hit
  40, that would mean inventing codes the source doc does not have.
