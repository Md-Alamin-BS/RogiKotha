## Fragile or surprising

- **The append-only trigger almost broke its own escape hatch.** `fn_block_mutation()` blocked every
  `DELETE` on `audit_events` unconditionally at first, including the one `fn_expire_audit` itself
  issues — the retention-expiry function could never have deleted anything. Fixed with a
  transaction-local `rk.audit_expiry` flag that only `fn_expire_audit` sets (`ISS-126`). If you add
  another `SECURITY DEFINER` function that needs to mutate an append-only table, follow the same
  pattern — do not weaken `fn_block_mutation()`'s default in any other way.
- **drizzle-orm 0.45 wraps driver errors.** `error.message` on a failed `testDb.insert(...)`/`.update(...)`
  is a generic "Failed query: ..." string; the actual PostgreSQL message (what a CHECK/trigger/unique
  constraint really said) is on `error.cause.message`. Plain `pg.Pool` queries (used for the
  role-grant tests) do not have this problem — only drizzle-wrapped calls do. Both int test files add
  a local `expectPgError` helper for this; reuse it rather than plain `.rejects.toThrow(...)` when
  asserting on a database-side rejection through Drizzle.
- **Migration numbering is drizzle-kit's own, not the task text's.** The four new migrations are
  `0002_content.sql`/`0003_triggers.sql`/`0004_deferred_fks.sql`/`0005_grants_part2.sql`, one lower
  than the task file's `0003`/`0004`/`0005`/`0006` (`ISS-125`, same class as `ISS-085`). If you ever
  need to hand-write another custom migration in this package, use
  `drizzle-kit generate --custom --name <name>` (not a hand-edited journal entry) so the snapshot
  `id`/`prevId` chain stays valid for the next `drizzle-kit generate`.
- Five FKs from data-model §16 note 1 could not be plain Drizzle `.references()` calls — four to
  avoid circular imports between schema files, one (`evidence_items.published_artifact_id`) because
  Drizzle 0.45 has no `deferrable`/`initiallyDeferred` option at all (`ISS-129`). All five live in
  `migrations/0004_deferred_fks.sql` as raw SQL instead.
