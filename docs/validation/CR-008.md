## Hard-rule evidence checked

- **No number stands for quality / counts are rows.** MOD-2033's 6/6 is matched by 6 real
  `reports` rows and a reason sum of 6 (live query). The seed adds no stored aggregate.
- **Reporter identity never reaches the reported party.** All 10 `reports` rows come from
  `reporter_1..6`. Count of reports from any other account: **0**. Notification `params` never
  carry a reporter. n3 carries only `caseCode`, `commentPublicId` and `reviewPublicId`.
- **Audit/notification details allowlisted.** Verified on the five live rows: `params` hold public
  ids and a case code only. No email, filename, body or the corpus's free-text `text.en/bn`.
- **Bengali and English.** All five `message_key`s exist in both files. Parity stays at **777**.
  CR-008 adds no keys and does not touch `bn.json`/`en.json`.
- **Synthetic marker.** Checked the rendered pixels of the regenerated `fixtures/photo.jpg`: the red
  `DEMO — SYNTHETIC DOCUMENT — NOT A REAL PATIENT RECORD` line is at the top. Only EXIF changed. The
  GPS point (23°45′N 90°23′E) is a generic city-centre coordinate, not a private location. The
  names in the fixture come from the existing synthetic corpus template, and no new name was
  authored.
- **Facility feedback never enters a doctor's aggregates (fakes).** The new `criteriaDistribution`
  reads only `facilityReviews`. `sentiment/outcomeDistribution` read only `reviews`. The stores are
  separate (`repositories.ts:271-279`).
- **No agent/tool attribution.** `git log main..HEAD --format='%an <%ae>%n%cn <%ce>%n%B'`: both
  commits are authored and committed by the human's own identity, with no trailer. Grepping every
  added line for tool and model names matches only the sanctioned `Run record` fields in
  `docs/implementation/`.
- **Files outside owned paths.** Only `src/builders/case.ts` falls outside them (declared;
  `ISS-225` (c)). `seed-notifications.ts` is the "own step file" step 1 permits. The register files
  are step 6.
- **Dependency check.** sharp was vetted on 2026-09-13 (T-007), one day before CR-008 was
  authored. That is under the 3-day window, so no new entry was required.
