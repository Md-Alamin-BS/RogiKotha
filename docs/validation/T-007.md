## Hard-rule evidence checked

All eight ticked items were re-verified independently rather than read:

- **No number stands for quality.** No column anywhere in the 58-table schema matches
  `rating|score|stars|grade|average|avg_`. `reviews` carries no cached `count`/`like`/`dislike`
  column — the counts are real `reactions` rows: r1 has **34 like + 2 dislike** rows, exactly the
  prototype's `likes: 34, dislikes: 2`.
- **Missing values are absent, never `0`.** `evidence_items.retention_expires_at` is `null` for the
  failed item e5 and a real date for the other six; facility-review `criteria` keep the corpus's
  `null` entries.
- **Facility feedback never enters a doctor's aggregates.** `seed.int.test.ts`'s third test asserts
  `facility_reviews` has no column matching `%doctor%` — re-run green. Note this is a **structural**
  proof, not a query-level one; there is no query layer yet, and the fakes that would carry the
  query-level test are missing their distribution methods (`ISS-177`).
- **Reporter identity never reaches the reported person.** All **7** report rows are filed by
  `reporter_1..6` accounts; the count of reports filed by any account whose username is not
  `reporter_%` is **0**, so no content author reports anything and the reporter pool is disjoint from
  every authoring account.
- **Original evidence is never served publicly.** `kind='original' and public` = 0, and in fact no
  `original` artifact row exists at all (see `ISS-181`).
- **Synthetic marker still visible.** Verified by **looking at the rendered pixels**, not the source:
  `.data/storage/public/<item>/thumb.png` and `fixtures/prescription-1.jpg` both show
  `DEMO — SYNTHETIC DOCUMENT — NOT A REAL PATIENT RECORD` in red at the top of the page.
- **No real person or facility named negatively.** The corpus is a verbatim port; the diff of
  `port-corpus.mjs` authors no names. Re-running the port produces content-identical output.
- **No agent/tool attribution.** `git log --format='%an <%ae>%n%cn <%ce>%n%B'` over all three commits:
  every one authored **and** committed by the human's own git identity, no trailer. Grepping every
  added line under `packages/`, `apps/` and `.gitignore` for the names of every AI tool and model
  family in use: **no match**.

Also checked for G4: **no file outside the owned paths** — the only two non-`packages/test-support/`,
non-`docs/` files are `.gitignore` (explicitly owned: "Modify ... `.gitignore`") and `pnpm-lock.yaml`
(the consequence of the three dependencies step 1 authorises). `docs/status/dependency-check-log.md`
carries a correct dated entry, which `AGENTS.md` requires. **No i18n edit was needed** — parity stays
at 777 keys, because the five `notif.*` keys step 6 pre-authorised were already ported by T-006 (which
is also why `ISS-173`'s fix needs no i18n change). Nothing in `apps/` imports `@rogikotha/test-support`;
`apps/web/package.json` lists it as a **devDependency** only, and that predates this task.

`ISS-169` (the `STORAGE_ROOT` bug the implementer found and fixed mid-task) was verified as a **fix,
not a symptom**, as `NEXT.md` asked: the resolution logic at `seed-evidence.ts:27-30` anchors a
relative `STORAGE_ROOT` at the repo root and passes absolute values through, and a live seed run from
`pnpm --filter` (working directory `packages/test-support`) wrote to the repo-root

- **`ISS-158` + `ISS-176` are one question.** `05-demo-storyboard.md` disagrees with the prototype
  data twice: it names `anon_author_r4` as the alias-isolation proof (r4 is pseudonymous; r2/r8/r12

  `S2`s are the same failure mode: a step's *mechanism* was built correctly and its *data* quietly
  fell short, in a place the task's own acceptance check could not see (a table nobody counted, a
  number the port dropped, an EXIF block sharp silently ignored). Acceptance rows that assert
  "something is present" rather than "this exact thing is present" are where that hides.

  (`eslint.config.mjs:52`, T-010). Until T-010 merges, "lint incl. boundaries" in the G1 gate means
